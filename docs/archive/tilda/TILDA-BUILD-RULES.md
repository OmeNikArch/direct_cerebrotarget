# Правила проектирования лендинга для переноса в Tilda

Этот сайт проектируется как исходник для Figma и переноса через плагин Figma to Tilda. HTML to Design используем только для получения исходного макета в Figma. Затем плагин переносит подготовленные слои из Figma прямо в редактируемые Zero Block Tilda.

## Основной принцип

Один смысловой раздел лендинга = один самостоятельный Figma Frame = один Zero Block в Tilda. Не собираем всю страницу в одном Frame/Zero Block и не вставляем готовую страницу единым HTML-кодом.

## Что используем

- Zero Block, импортированный из Figma через плагин, — основной способ переноса визуальных секций.
- Обычные блоки Tilda можно оставить для функциональных частей: меню, FAQ, формы, футера. Это не требование, а практичный выбор, если такие элементы должны особенно легко настраиваться.
- Нативную форму Tilda — для всех заявок. Она позволит подключить почту, Telegram, CRM или Tilda Leads без переделки страницы.
- T123 или HTML-элемент в Zero Block — только для изолированных дополнений, которые невозможно собрать штатно. Свои стили и скрипты в нём должны иметь уникальные классы или ID, чтобы не влиять на остальные блоки.

## Ограничения для макета и кода

- Не завязывать смысловую часть на сложную анимацию, canvas, WebGL, нестандартные скролл-эффекты и JavaScript-виджеты.
- Не делать интерактивные элементы, критичные для пути к заявке, только через код. Кнопки должны вести на якорь, попап или нативную форму Tilda.
- Все тексты, названия карточек, CTA, цены и контакты должны быть самостоятельными текстовыми слоями, а не частью изображения.
- Карточки, шаги и FAQ должны иметь повторяемую структуру: заголовок, короткий текст, при необходимости ссылка. Это ускоряет их замену в Tilda.
- Изображения, когда появятся, хранить отдельными файлами с понятными названиями. Не встраивать текст в иллюстрации.
- Не использовать в макете элементы, требующие абсолютного позиционирования без необходимости; на мобильном они чаще требуют ручной пересборки.

## Подготовка Figma для плагина Figma to Tilda

- Каждый будущий Zero Block оформляем отдельным корневым Frame шириной 1200 px.
- Импортируем по одному Frame в один Zero Block. Не передаём весь лендинг одним полотном.
- Вложенность групп — не более шести уровней, иначе глубоко вложенные элементы не перенесутся.
- Кнопка — это группа из фона и текста, в названии которой есть `button`. Текст внутри должен быть выровнен по ширине фона кнопки.
- Группы, которые нужно превратить в одно растровое изображение, называем с `image`; для векторной передачи — с `svg`. Обычный текст, карточки и кнопки не объединяем в изображения: они должны остаться редактируемыми.
- Сохраняем понятные имена слоёв: `hero-title`, `hero-cta-button`, `process-card-01`. Это поможет быстро ориентироваться после импорта.
- Фоны задаём на корневом Frame, если они должны стать фоном артборда Zero Block.

## Сетка и адаптив

- Рабочая десктопная ширина каждого уникального раздела — 1200 px. Это соответствует рекомендуемой Tilda ширине для импорта одного Frame в один Zero Block.
- В Figma переносим по одному Frame на один будущий Zero Block, а не весь лендинг одним Frame.
- Для Zero Block проверяем пять диапазонов: 1200+, 980–1200, 640–980, 480–640 и 320–480 px.
- Для стандартных блоков используем их встроенный адаптив и отдельно проверяем мобильный вид после публикации.
- На мобильном: одна колонка для карточек, кнопка не уже 44 px по высоте, текст не должен обрезаться или накладываться.

## Перед публикацией в Tilda

- Подключить приёмщик формы и протестировать заявку на опубликованной странице.
- Добавить настоящую политику обработки персональных данных и ссылку в чекбокс формы.
- Проверить ссылки, якоря, меню, попапы и все версии экрана.
- Заменить шаблонные кейсы, контакты, реквизиты и обещания только на подтверждённые данные.

## Как будем работать

1. Дорабатываем сайт в коде и проверяем логику/адаптив.
2. Импортируем результат через HTML to Design в Figma.
3. Подготавливаем Figma: разделяем сайт на фреймы, именуем слои и готовим кнопки/группы по правилам плагина.
4. Переносим каждый Frame плагином Figma to Tilda в отдельный Zero Block и добавляем нативные настройки формы, ссылок и адаптива.
5. Тестируем опубликованную версию.

Основано на официальных рекомендациях Tilda по [импорту из Figma](https://help-ru.tilda.cc/zero/figma-import), [Zero Block](https://help-ru.tilda.cc/zero), [адаптивной версии](https://help-ru.tilda.cc/mobile-version) и [вставке HTML-кода](https://help-ru.tilda.cc/html).

# Лендинг «Церебро Директ»

Адаптивный лендинг услуги настройки и ведения Яндекс Директа. Проект публикуется напрямую на отдельном домене; Tilda и перенос через Figma не используются.

Для быстрого старта в Codex сначала прочитайте [PROJECT-CONTEXT.md](PROJECT-CONTEXT.md): в нём собраны актуальный статус, ключевые файлы и следующие действия.

## Структура

- `site/index.html` — разметка страницы и стили Tailwind
- `site/script.js` — данные секций и интерактивные элементы
- `site/form-logic.mjs` — валидация формы
- `site/assets/` — изображения
- `site/*.test.mjs` — автоматические проверки

## Локальный запуск

Нужен Node.js. Из корня проекта запустите статический сервер:

```powershell
npx serve site
```

Откройте адрес, который появится в терминале. Для запуска тестов:

```powershell
node --test site/*.test.mjs
```

## Подключение формы

Форма `#lead-form` находится в `site/index.html`. Backend endpoint указывается в атрибуте `data-endpoint`. Пока значение пустое, форма намеренно показывает ошибку и не имитирует успешную отправку.

Запрос отправляется методом `POST` в JSON со следующими полями:

- `name` — имя
- `phone` — телефон
- `email` — почта
- `request_type` — `promotion` или `audit`
- `contact_method` — `telegram`, `phone` или `email`
- `profile` — ник или ссылка в Telegram; обязательны только для Telegram
- `consent` — согласие на обработку персональных данных

Frontend ожидает любой успешный HTTP-статус `2xx`. Другой статус или сетевая ошибка переводят форму в состояние ошибки. Интерфейс формы поддерживает состояния `idle`, `submitting`, `success` и `error` через `data-state`.

Интеграцию с Битрикс24, хранение секретов и серверную валидацию выполняет backend. Вебхуки, токены и `.env` нельзя добавлять в Git.

## Работа на двух компьютерах

Основной способ синхронизации — приватный Git-репозиторий: на втором компьютере клонируйте его, откройте корневую папку в Codex и начните с `PROJECT-CONTEXT.md`.

Если переносите проект вручную, копируйте `site/`, `docs/`, `AGENTS.md`, `PROJECT-CONTEXT.md`, `README.md` и `.gitignore`. Не переносите `.git/`, `.npm-cache/`, `node_modules/`, `.env` и другие локальные данные.

Ветка `main` считается стабильной. Новые изменения вносите в отдельных ветках и объединяйте после проверки.
